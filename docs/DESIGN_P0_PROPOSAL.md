# 设计 P0 项方案（评审整改 · 第二弹）

> 评审原话：「你把 90% 的精力花在『让这个游戏跑得很稳』上，而『这个游戏值不值得玩』从头到尾没人审过。」
> 本轮只出**书面方案**（评审规定：改设计 = 先想清楚），不写代码。逐项给出现状、评审原话、候选方案、影响范围、风险，由你拍板后再动代码。

## 0. 一句话结论

评审的 5 个设计 P0 项指向同一个根因：**决策点密度太低**。
每轮 15 个阶段里 10 个是自动播放、能改变结果的输入只有 4 个（买/出牌/terrorist 目标/swap 目标）、计分「1 票之差=10 票之差」让风险不付报酬、卡池 122 张里 tagBoost 换皮 30+ 次。

**方案总纲（都含回退路径，可逐项独立实施/回滚）：**

| # | 项 | 评审等级 | 建议 | 预计改动面 |
|---|---|---|---|---|
| 1 | 流程 16→8 步 | P0 | 合并零决策阶段 | 引擎 PHASES + 前端阶段条 |
| 2 | 通用质证机制 | P0 | terrorist 泛化为付费质证权 | 引擎 + 前端交互 + AI |
| 3 | 赢家通吃计分 | P0 | 第一名 4 分、其余 1 分 | 引擎 doSettle/beginIncome |
| 4 | 修 2 人局 | P0 | 位置技能改为座位无关条件 | 引擎 SKILLS + 测试 |
| 5 | 卡池 122→30 | P0 | 每技能保留 1 张代表作 | 数据 + 平衡测试 |
| 6 | 双端渲染合并 | P1（修债） | 删 singleplayer 渲染副本 | 前端，可最后做 |

## 1. 流程 16→8 步精简（P0）

### 评审原话
> 「砍流程：16 步 → 8 步。删掉 drawEvent / drawVoter / settle / income 这类零决策的瞬时阶段，把 reveal+count 合并成一个可交互的『庭审回合』。」
> 「每轮 15 阶段，真需玩家输入只有买/举证/恐怖分子目标/换位目标/事件……其余 10 个阶段全是自动播放。」
> 「80 步流程、20 个决策点、一半还是可计算决策——这不是博弈。」

### 现状（引擎代码依据）
`shared/engine/05-phases.js` PHASES 表，16 个状态：
```
pickChar → chooseStarter → drawEvent → drawVoter → buy → play → reveal
→ preEvent → count → postEvent → rank → settle → discard → income → gameover
```
- `drawEvent` / `drawVoter`：`needsInput: () => false`，纯自动跳转（05-phases.js L27-28）。
- `preEvent` / `postEvent` / `rank` / `settle`：事件自动结算 / 排名公告 / 计分，均无输入。
- 每轮真正需要玩家输入的只有 4 处：`buy`（买/刷新/锁）、`play`（出牌）、`reveal`（terrorist 选目标）、`count`（swap 换位目标）。

### 方案（推荐：合并 + 保留状态机核心）
把 16 步折叠成 8 个**对玩家可见的回合节拍**：

```
选角 → 开局 → 【购买回合】 → 【举证回合】 → 【庭审回合】(亮牌+质证+事件+计票) → 【整理】 → 【收入】→ 终局
```

引擎实现上**不动状态机骨架**（17 分片 + 可序列化 rng 是刚修好的地基，不碰），只做两件事：
1. **阶段条合并**：`drawEvent/drawVoter` 标记为 `hidden: true`（前端不显示、不播放动画），逻辑照走。前端阶段条从 16 格变 8 格，纯展示层改动。
2. **reveal+preEvent+count 合并为「庭审回合」**：前端把这三个子阶段渲染成同一屏的连续交互（亮牌动画 → 质证区 → 事件飘字 → 计票），玩家视角是一次连贯审议。

### 备选方案（更激进，风险高）
真删阶段：`drawEvent/drawVoter/settle/income` 从 PHASES 删除，逻辑并入相邻阶段。**不推荐**——改 PHASES 表会动刚通过全量测试的状态机序列化，收益只是省 4 个内部标签，不值。

### 影响范围
- 引擎：仅 `05-phases.js` 加 `hidden` 标记（约 2 行/阶段）。
- 前端：阶段条渲染 + 庭审回合合并（`client.js`/`singleplayer.html` 的 UIPresenter）。
- 测试：`_smoke_game.js` 等依赖阶段名的断言需同步（预计 5-10 处）。
- 风险：**低**。状态机不变，纯视图折叠。

## 2. 通用质证机制（P0）

### 评审原话
> 「把 terrorist 机制扩成通用『质证』：每轮每个玩家有限次『质证权』，亮牌后、计票前，花 ⊙ 选择对手一张牌——翻面查看、或对其施加压制。」
> 「doCountContinue 是纯确定性函数，reveal 后到计票结束无任何改变结果的输入——最高潮（审议）是不可交互的幻灯片。」

### 现状（引擎代码依据）
- `terrorist`（证据排除，lv1，when:'reveal'）：**唯一**在亮牌阶段交互的技能（`06-actions.js` revealPending 流程）。
- `count` 阶段只有 `swapPending`（swap/shiftLeft/shiftRight 换位）一个输入点；其余 60+ 技能全部是 doCountContinue 里的确定性结算（`10-rank.js`/`12-income.js`）。
- 结论成立：从 reveal 完到 rank 出炉，玩家唯一能做的只有「换位」，审议高潮不可交互。

### 方案（推荐：质证权 = 花 ⊙ 的通用行动，与 terrorist 共存）
**每轮每人 2 次质证权**（可用 ⊙ 补充，第 3 次起每次 2⊙；或直接「每次 1⊙，上限 3 次」——数值待定）：

- **时机**：亮牌全部完成后、`preEvent` 前，插入 `crossEx` 子阶段（在 count 前，正好卡进「庭审回合」）。
- **动作 A 翻面查看**：花 1⊙ 选对手 1 张**未亮**牌，翻面查看（本牌进入公开区，但仍计入对方票数）。破「信息不对称」。
- **动作 B 施压压制**：花 1⊙ 选对手 1 张已亮牌，令其 -1 票（可叠加，但同一张牌最多被压 2 次）。
- **交互顺序**：座位序轮询，每人「质证 or 过」，所有人过完 → 进入事件/计票。
- **AI**：`14-ai.js` 加简单策略（领先时压制对方最高票牌、落后时翻面查关键牌）。

### 备选方案
- **B1（零新阶段）**：质证做成「回合制行动池」而非独立阶段——买/出牌后剩余 ⊙ 可在庭审回合随时发动。交互更自由，但引擎要支持「行动打断」，改动大。**暂不推荐**。
- **B2（最小版）**：只做「翻面查看」，不做压制——信息博弈已能拉高决策密度。改动最小。

### 影响范围
- 引擎：新阶段 `crossEx`（`05-phases.js`）+ 新 action（`06-actions.js`）+ doCountContinue 前插入压制扣票。
- 前端：庭审回合内新增质证区（选对手牌 + 确认），联机/单机两套。
- AI：策略函数。
- 测试：质证流程 smoke + AI 策略测试。
- 风险：**中**。新增阶段会动 PHASES 序列化（刚修好 rng），但阶段是追加不是改动，序列化兼容；关键是前端交互面最大，建议 B2 先行验证手感。

## 3. 赢家通吃计分（P0）

### 评审原话
> 「把差额计分改成『赢家通吃 + 小额保底』（第一 4 分、其余 1 分）。」
> 「doSettle `Math.max(1, reward - idx)` + beginIncome 保底 = 『1 票之差和 10 票之差只差 1 分』」
> 「风险不付报酬」「最优策略永远是打期望值最高的牌——这就是博弈的死因。」

### 现状（引擎代码依据）
`shared/engine/13-apply.js` doSettle：
```js
let r = Math.max(1, reward - idx);   // reward = rewardOf(round) = 2/3/4
s.support += r;
```
`shared/engine/14-ai.js` beginIncome：
```js
if (i === first) amt -= 1;   // 榜首 -1⊙
if (i === last) amt += 1;    // 末位 +1⊙
const pay = Math.max(1, amt); // 每轮保底 +1⊙
```
- 2 人局：第一 +2/+3/+4，第二恒 +1 → 票差只在第一名奖励里体现一次，第二名无论 1 票差还是 20 票差都 +1。
- beginIncome 的榜首 -1 / 末位 +1 / 保底 +1 是三重「反滚雪球」，评审点名批评。

### 方案（推荐：赢家通吃 + 小额保底，砍掉经济层反滚雪球）
```
doSettle：第一名 +4，其余 +1（无论几人局、无论票差）
beginIncome：删掉「榜首 -1 / 末位 +1 / 每轮保底」，
             改为固定 incomeOf(round)（第 1-3 轮 2⊙、第 4 轮 3⊙、第 5 轮 4⊙）
```
- **票差变值钱**：赢一轮 +4 分 vs 输一轮 +1 分 = 每轮 3 分落差，5 轮最多 15 分落差，决策压力拉满。
- **反滚雪球交给牌局本身**（hailMary/flipNarrative/momentum 等翻盘技），不再靠经济平账。
- 支持度上限判定（终局 21 分？）需同步重算——现在 5 轮满分 20，改动后满分 = 4+1×3（每轮）+ 角色加成，重新标定终局阈值。

### 备选方案
- **B1（保守版）**：第一 +4 / 其余 +1，但保留「榜首 -1⊙」作为唯一反滚雪球。改动减半，博弈张力提升有限。
- **B2（激进版）**：赢家通吃彻底（第一全拿、其余 0），滚雪球风险最高，**不推荐**。

### 影响范围
- 引擎：`13-apply.js` doSettle + `14-ai.js` beginIncome + `03-state.js` incomeOf/rewardOf。
- 平衡测试：`_balance_test.js` 全权重重跑，终局阈值重标定。
- 前端：计分展示文案（「陪审团倾向 +4」）无需改，金额飘字逻辑同步。
- 风险：**中**。数值是游戏灵魂，改完必须重跑 balance 测试（已有 2 项 + 千局模拟脚本）。

## 4. 修 2 人局（P0）

### 评审原话
> 「要么 solo 默认 4 座，要么把位置技能（flank/rally/firstSeat/leftWall…）改成座位无关的条件（已亮牌数/票数差/轮次）。」
> 实测佐证：2p agg-vs-hoard 71.7%（多打牌无成本 → 无条件占优，结构性失衡）。

### 现状（引擎代码依据）
- 2 人局座位相邻关系退化为「你的牌左右都是敌方牌」：
  - `flank`（相邻有本方牌 → 最高敌 -1）：2 人局**永不触发**（相邻全是敌）。
  - `rally`（相邻有本方牌 → 本方 +1）：同上，**永哑**。
  - `counsel`（左右都本方 +2 / 相邻本方 +1）：2 人局恒取 +1 分支，退化。
  - `leftWall`（左半区本方各 +1）：2 人局仍可用但收益减半。
- 2p 无竞争压力 → 「多打牌无成本」→ agg 无条件占优（71.7% 实测）。

### 方案（推荐：位置技能条件化，双轨语义）
把「相邻/半区」类技能在 **2 人局自动替换为座位无关条件**（3-4 人局保持原逻辑）：

| 技能 | 3-4 人局（现状） | 2 人局（替换后） |
|---|---|---|
| flank 左右夹击 | 相邻有本方牌 → 最高敌 -1 | 本方已亮 ≥2 → 最高敌 -1 |
| rally 旁听声援 | 相邻有本方牌 → 本方 +1 | 本方已亮 ≥2 → 本方 +1 |
| counsel 攻守同盟 | 左右都本方 +2 / 相邻本方 +1 | 本方已亮 ≥3 → +2 / ≥1 → +1 |
| leftWall 左翼壁垒 | 左半区本方各 +1 | 本方已亮 ≥3 → 本方 +1 |
| firstSeat/lastSeat | 行首/行尾是敌 → -1 | 保留（行首尾概念 2 人局仍成立） |
| pivot 险中取胜 | 左右都敌 → +2 | 敌方已亮 ≥2 → +2 |

> 语义统一为「铺场条件」：2 人局的博弈核心从「抢位置」变成「抢铺场节奏」——与 agg/hoard 流派直接对抗（agg 铺得凶 → rally/flank 反而触发）。

### 备选方案
- **B1（评审第一选项）**：solo 默认 4 座（2 AI 陪打）。不推荐——AI 陪打是「伪装 2p」，真实 2p 对战问题依旧。
- **B2（最小版）**：只改 flank/rally/counsel 三个最退化的技能，其余不动。可先上，验证后再扩。

### 影响范围
- 引擎：`10-rank.js`/`12-income.js` 技能判定加 `if (seatCount === 2)` 条件分支。
- 测试：`_test_strategy_diversity.js`（2p agg-vs-bal 58.7%）重跑，目标压回 50-55% 区间；新增 2p 专项平衡断言。
- 风险：**中**。技能语义双轨增加维护成本，但用注释 + 单一函数 `posCond(owner)` 收口可降。

## 5. 卡池精简 122→30（P0）

### 评审原话
> 「122 张里 tagBoost 出现 30+ 次——同技能换皮。30 张有真实组合关系的卡，胜过 122 张填充卡。卡池深度 ≠ 卡牌数量。」

### 现状（引擎代码依据）
`shared/engine/01-data.js` VOTER_TEMPLATES 实测（grep 确认）：
- 选民牌 **120 张**（v01-v100+），tagBoost（本方 +1 票）**换皮 33+ 次**（学生/老兵/教友/码农/教授/创投人/维权者/牧师/主妇/移民/执事/学贷/店主/教师/管道工/街头活动家/租户/农场主/卡车司机/巡边员/诊所义工/单亲妈妈/电台主持/阴谋论者/电视布道家/教师/家教家长/跨性别者/强硬警长/民粹商家/自由派/环保青年/流浪者/医护/主播/书店/咖啡/房产/军商/乡村歌手/健身/数据科学家/快递站长…）。
- tagHate（最高敌 -1）也换皮 ~15 次。同一技能的 3 张换皮卡 = 3 张一模一样的牌，只改名字。

### 方案（推荐：每技能 1 张代表作，总量 ~40）
- **保留全部 60+ 独特技能**（SKILLS 词典不动），但 VOTER_TEMPLATES **每个技能族只保留 1-2 张代表性卡**（按数值梯度：如 tagBoost 留 cost1/cost2/cost4 三档各 1 张）。
- 目标总量：**~30-40 张**（评审说 30，建议留 36 张整数梯度，卡组构筑更清晰）。
- 换皮卡删除后，市场刷牌逻辑不变（从 30 张池抽），但**单卡出现频率提高** → 玩家更快记住「哪张牌什么技能」，组合套路可学。
- 事件牌（EVENTS）独立保留，不在本次 30 张范围内。

### 影响范围
- 数据：`01-data.js` VOTER_TEMPLATES 重写（约 120 → 36 条）。
- 平衡：`_balance_test.js` 权重重跑（卡池变小，各技能价值曲线变化）。
- 文档：`LEGAL_CASES_DESIGN.md` 中逐卡注释需同步裁剪。
- 风险：**低-中**。纯数据删减不动引擎；唯一风险是删掉换皮卡后市场多样性下降——用「每技能梯度保留」规避。

## 6. 双端渲染合并（P1 工程债）

### 评审原话
> 渲染收口是「未完成工作被包装成设计决定」：singleplayer.html 的渲染副本该删，全走 shared/render-core.js。

### 现状
- `shared/render-core.js` 存在；`singleplayer.html` 内部仍有一份渲染实现（external script `shared/game-core.js` + 内联渲染）。
- `client.js`（联机）与 singleplayer 渲染路径分叉，特效/计票动画两套实现。

### 方案
- 把 singleplayer.html 的渲染改为 import `shared/render-core.js`，删除内联副本。
- 依赖第 1 项「庭审回合合并」先落地（渲染合并与阶段条重构同屏，一起做成本更低）。

### 影响范围
- 纯前端；测试：`_render_test.js`（7 项）重跑。
- 风险：**中**（渲染重构易出回归），排在最后做。

## 7. 建议执行顺序（若你全部拍板）

```
第 1 批（低风险快赢）：5 卡池精简 → 3 赢家通吃计分 → 4 修 2 人局
      ↓ 重跑 balance + strategy 测试，数值锁定
第 2 批（核心玩法）：2 质证机制（先 B2 翻面版验证手感）
      ↓ 前端试玩
第 3 批（体验收口）：1 流程 16→8（隐藏阶段 + 庭审回合）→ 6 双端渲染合并
      ↓ 全量测试 + 联机/单机浏览器验证 → 提交
```

每批独立提交、可独立回滚。你只需回答：**全部采纳 / 部分采纳（指明哪几项）/ 先做哪几项**。
